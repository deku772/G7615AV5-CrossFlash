# IPTV 单线复用（一根网线同时跑上网 + IPTV）

> 目标：光猫只拉一根线到路由器，路由器后面既能上网、又能给机顶盒看 IPTV，机顶盒保持 PPPoE 拨号。
> 本文是 2026-11-01 在 G7615AV5（联通 V3.0.5P1N4）上**实机跑通并用抓包验证**的完整方案。

---

## 一、先说结论

```
光猫 LAN1（Trunk：VLAN48 tagged + VLAN3185 tagged）
        │  一根网线
        ▼
   路由器 WAN 口
        ├─ 上网流（VLAN48）→ PPPoE 拨号 → LAN 口给电脑
        └─ IPTV 流（VLAN3185）→ 剥离标签 → 指定 LAN 口 → 机顶盒 PPPoE 拨号
```

三句话概括配置：

1. **光猫**：把 LAN1 的绑定模式从「端口绑定」改成「**VLAN 绑定**」，填 `48/48` 和 `3185/3185`。
2. **路由器**：IPTV 功能开启，VLAN 填 `3185`，指定一个 LAN 口给机顶盒。
3. **机顶盒**：PPPoE 拨号（填 IPTV 专网账号），**不要 DHCP**。

---

## 二、★ 核心：端口绑定 和 VLAN 绑定 完全是两回事

这是全网教程最容易讲混的地方，也是绝大多数人卡住的原因。

| | 端口绑定（PortBinding） | VLAN 绑定（VlanPortMask） |
|---|---|---|
| 本质 | 某条 WAN 独占某几个物理口，光猫**剥掉**标签送出去 | 端口变 Trunk，标签**原样透传** |
| 同一口多业务 | ❌ 页面互斥，选了一个另一个被取消 | ✅ 可以，多个 WAN 在同一 bit 上置位 |
| 网页表现 | 一个复选框矩阵，一格只能打一个勾 | 每个端口一个输入框，可填多行 `用户VLAN/运营商VLAN` |
| 适用场景 | 机顶盒直连光猫指定口 | **单线复用** |

### 你会遇到的"互斥"现象

在「端口绑定」页面把 LAN1 勾给 IPTV 后，INTERNET 那一行里 LAN1 的勾**自动消失**。
这不是 bug，也不是"设备不支持"——**是这个页面只允许一口一 WAN**。

底层其实支持共存。看数据层就明白了：

```xml
<Tbl name="MultiWancConfProduct" RowCount="4">
  <!-- INTERNET: PortMask 覆盖全部端口，VlanPortMask 的 bit0 = LAN1 打 VLAN48 标签 -->
  <Row No="2"><DM name="PortMask" val="131071"/><DM name="VlanPortMask" val="1"/></Row>
  <!-- IPTV: 不占端口(PortMask 空)，VlanPortMask 含 bit0 = LAN1 打 VLAN3185 标签 -->
  <Row No="3"><DM name="VlanPortMask" val="32785"/></Row>
</Tbl>
```

### 位掩码对照表

`PortMask` 和 `VlanPortMask` 用的是同一套 bit 定义：

| bit | 端口 | bit | 端口 |
|---|---|---|---|
| 0 | LAN1 | 8 | WLAN1（2.4G） |
| 1 | LAN2 | 11 | WLAN4 |
| 2 | LAN3 | 12 | WLAN5（5G） |
| 3 | LAN4 | | |

验算：

- `131071` = `0x1FFFF` = bit0~bit16 全置位 → INTERNET 覆盖所有端口
- `VlanPortMask = 1` → 只在 LAN1 打标签
- `VlanPortMask = 32785` = `32768 + 16 + 1` = bit15 + bit4 + bit0 → LAN1 + 两个内部口

**两个 WAN 的掩码在 bit0 上重叠，这就是"同一个口能同时跑两路业务"的真正含义。**

## 三、操作步骤（网页）

### Step 1 · 光猫：取消端口绑定

「基本配置 → 绑定设置」：

1. 绑定模式选「**端口绑定**」；
2. 把所有 WAN 前面勾选的 LAN 口**全部取消**（这一步是清空 `PortBinding` 表）；
3. 保存。

> 清空后不会断网。因为清空 = 不限制，所有口默认可达，而不是"没有口能用"。

### Step 2 · 光猫：给 LAN1 做 VLAN 绑定

同一个页面，把绑定模式切成「**VLAN 绑定**」，在 **LAN1** 的输入框里填：

```
48/48
3185/3185
```

格式是 **`用户侧 VLAN / 运营商侧 VLAN`**，一行一条，一一映射就是"透传"。

- `48/48` → 上网（INTERNET 的 VLAN 是 48）
- `3185/3185` → IPTV（本例运营商的 IPTV VLAN 是 3185）

> ⚠️ 只填 `3185` 不够。如果你还需要上网流量也走这个口，`48/48` 必须一起填。
> 有些教程写"每个 LAN 口填 3185 就行"，那是**只做 IPTV、不管上网**的场景。

### Step 3 · 路由器：IPTV VLAN 剥离

在路由器的 IPTV 设置页：

| 项 | 值 |
|---|---|
| IPTV 功能 | 开启 |
| 模式 | 单线复用 / 不使用光猫 IPTV 口 |
| VLAN ID | `3185` |
| 指定 LAN 口 | 任选一个（例 LAN2），机顶盒只能插这个口 |

> ★ 这一项能不能生效，取决于路由器的**接线方式**：
> - **WAN 口进线**：IPTV VLAN 功能正常；
> - **LAN-LAN 桥接做 AP**：多数机型 IPTV 功能失效，不会剥离标签，机顶盒会报"网络接入不合规"。
>
> 如果你的路由器只能 LAN-LAN 桥接，用[下方备选方案](#六备选方案网管交换机)。

### Step 4 · 机顶盒：PPPoE 拨号

网络类型选 **PPPoE**，填 IPTV 专网账号密码，**不要选自动 DHCP**。

为什么必须是 PPPoE：光猫的 IPTV 连接是**桥接**（`3_IPTV_B_VID_3185`，`ConnType=2`），
它不提供 IP，只提供二层通道。机顶盒要靠 PPPoE 自己拨到运营商的 IPTV BRAS 上。

> PPPoE 是**二层协议**，只要二层通道干净（VLAN3185 透传、标签被正确剥离）就能拨通，
> 完全不需要光猫给 IPTV 分配地址。这也是为什么"IPTV 保持路由模式"的说法在 PPPoE 场景下是错的。

## 四、怎么验证真的成功了（抓包法）

光猫有 `tcpdump`，直接在设备上抓 LAN1：

```bash
# 抓 40 秒，统计标签分布
tcpdump -i eth0 -nn -e > /tmp/t1.txt 2>&1 & P=$!; sleep 40; kill $P; cat /tmp/t1.txt
```

> 设备内部口序：`eth0=LAN1`、`eth1=LAN2`、`eth2=LAN3`、`eth3=LAN4`。
> 别用 `ifconfig` 的序号猜，用 `brctl showmacs br0` 对 MAC 更准。

### 本例实测结果（40 秒 1511 帧）

```
825 帧  vlan 3185      ← IPTV
 27 帧  vlan 48        ← 上网
659 帧  无标签          ← 路由器下设备的本地流量
```

### 判定成功的三个铁证

```
① 机顶盒的 PPPoE 会话已建立
d4:c1:c8:8c:92:00 > fc:57:03:76:fd:cc  vlan 3185  PPPoE [ses 0x8852]
   IP 10.111.16.1 > 225.0.4.74: igmp query v2

② 机顶盒拿到了专网 IP，并在主动加入组播
fc:57:03:76:fd:cc > d4:c1:c8:8c:92:00  vlan 3185  PPPoE [ses 0x8852]
   IP 10.142.70.90 > 225.0.4.74: igmp v2 report
```

| 看到什么 | 说明 |
|---|---|
| `PPPoE [ses 0x....]` | 拨号成功，二层通了 |
| 机顶盒源 IP 是 `10.x.x.x` | 拿到 IPTV 专网地址（不是 192.168 内网） |
| `igmp query` + `igmp report` 成对出现 | 组播通路正常，直播能看 |
| LAN1 同时出现 VLAN48 和 VLAN3185 | Trunk 生效，单线复用成立 |

## 五、排查：四层定位法

从下往上排，别一上来就改配置。

| 层 | 检查 | 命令 / 方法 | 不正常的表现 |
|---|---|---|---|
| 1 光猫标签 | LAN1 上有没有 VLAN3185 帧 | `tcpdump -i eth0` | 没有 3185 → VLAN 绑定没生效 |
| 2 光猫端口 | `PortMask` / `VlanPortMask` | `sendcmd 1 DB p MultiWancConfProduct` | bit0 没置位 |
| 3 路由器剥离 | 机顶盒口有没有裸的二层帧 | 机顶盒侧抓包 / 换直连测试 | 机顶盒报"接入不合规" → 标签没剥离 |
| 4 拨号 | 机顶盒是否拿到 10.x 地址 | 机顶盒状态页 | 678/691 → 账号错或通道不通 |

### 典型症状对照

| 症状 | 原因 | 处理 |
|---|---|---|
| 机顶盒报"网络接入不合规" | 收到**带标签**的帧，机顶盒不认 | 路由器没剥离 VLAN，或路由器 AP 模式功能失效 |
| 直播能看，点播/回看不行 | 只有组播通，单播通道没通 | 检查 IPTV 专网地址和 PPPoE 是否真拨上 |
| 上网正常，IPTV 完全没流 | LAN1 没做 VLAN 绑定 / 没填 3185 | 补 VLAN 绑定 |
| IPTV 正常，上网断 | 只填了 `3185/3185`，漏了 `48/48` | 补上网那条 |
| 一切都对，几天后失效 | TR069 重新下发了配置 | 关 `MgtServer.Tr069Enable`，见 [post-flash-runbook.md §3](post-flash-runbook.md#3-防止被运营商重新下发覆盖) |

## 六、备选方案：网管交换机

当路由器不支持 IPTV VLAN，或者只能 LAN-LAN 桥接时，用一台网管交换机硬拆：

```
光猫 LAN1（Trunk 48+3185）
        │
   ┌────▼─────┐
   │ 网管交换机 │
   └─┬──────┬─┘
     │      │
  Access   Access
  VLAN48   VLAN3185
     │      │
  路由器   机顶盒
```

- 上联口：Trunk，允许 48、3185
- 端口 A：Access VLAN48 → 接路由器 WAN
- 端口 B：Access VLAN3185 → 接机顶盒

交换机直接完成标签剥离，路由器随便做 AP，不受其 IPTV 功能限制，**成功率最高**。

## 七、两个必须记住的约束

1. **不要在「端口绑定」页面点保存。**
   那个页面一保存就会按"一口一 WAN"重写 `PortBinding`，把 VLAN 绑定的 Trunk 结构破坏掉。
   要调整就重新走一遍本流程，或从备份恢复。

2. **`VlanPortMask` 的 bit 只认端口，不认业务。**
   同一 bit 被 INTERNET 和 IPTV 同时置位是**正常且必需**的，
   不是配置冲突，不要去"消除"它。
